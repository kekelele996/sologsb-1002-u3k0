# 学术论文协作审阅台

面向作者、审稿人与编辑三类角色的论文协作审阅前端。正文、批注、讨论、建议、版本和冲突处理数据均保存在浏览器本地。

## 功能

- 三个独立工作区：
  - 作者可直接修改正文，逐条接受或拒绝审稿人的修改建议。
  - 审稿人可引用原文、添加段落批注、提出修改建议并回复讨论。
  - 编辑可合并同一段落的重复意见、锁定已确认段落并比较两个版本。
- 侧边目录、段落高亮、批注过滤、修订模式与版本差异表。
- `J` / `K` 在段落之间导航，`T` 切换修订模式，编辑角色可用 `L` 锁定或解锁段落；`Ctrl/⌘ + Z` 撤销，`Ctrl/⌘ + Y` 或 `Shift + Z` 重做。
- 完整撤销重做、手动保存和浏览器未保存提醒。
- 草稿自动写入 `localStorage`，刷新或断网后仍可继续。
- **本地待提交队列**：断网期间对段落正文、批注、回复、意见合并的改动先按条目攒在队列里（同段落连续编辑自动合并），队列与草稿一起持久化。
- **逐段对账**：网络恢复后队列自动与审阅服务逐段核对——只有 `queued / failed` 的条目会重发，已送达的不重复发送，`blocked / conflict` 等作者处理。
- **冲突双版本留存**：同一段落两边都改过时，本页版本与远端版本同时保留，由作者挑选一版；落选版本进入“落选版本存档”，随时可以找回重投。
- **服务端退回**：段落被编辑锁定、或远端已把意见合并时，本地改动退回队列（`blocked`），状态解除后一键重新提交。
- **失败续传**：同步中途失败（可在队列抽屉里开启“模拟弱网”）只把失败条目标记为 `failed` 留在队列，下次只补没送成功的段落；崩溃时正在发送的条目重载后自动退回待提交。
- 顶栏可切换联网/断网；“待提交队列”抽屉里能看到全部条目的状态、落选存档，并能模拟协作者在服务端改段落、锁定段落、合并意见来演示对账。
- 内置模拟接口。页面包含完整的示例论文、批注、回复、重复意见和两个历史版本。

## 技术栈

- React 19
- Vite + TypeScript
- Zustand
- Ant Design
- localStorage + 浏览器内模拟接口

## 本地开发

```bash
npm install
npm run dev
```

开发端口由 Vite 决定，源码不硬编码宿主端口。

## 生产构建

```bash
npm install
npm run build
npm run preview
```

## Docker

```bash
docker build -t sologsb-1002 .
docker run --rm -p 10002:80 sologsb-1002
```

容器内的 nginx 监听 `80`，访问 `http://localhost:10002`。
